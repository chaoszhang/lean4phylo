# lean4phylo

A formalization library for the classical algorithms of computational phylogenetics,
built on **Lean 4 + Mathlib** so that every claim is **machine-checked**.

> The name is a pun on **Lean 4** and **lean for** phylogenetics.

## Goal

Formalize the classical objects and algorithms of phylogenetics — trees, split systems,
quartets, tree metrics, reconstruction algorithms, statistical consistency — as a
**long-lived library of algorithm correctness**, not as a single headline theorem.
The target is: for every classical algorithm, its correctness has a machine-checked proof.

## Layout

```
Phylo.lean              root module (imports every submodule)
Phylo/
├── Core.lean           cladograms and basic lemmas
├── Split.lean          split systems · compatibility
├── Laminar.lean        laminar families · toCladogram · toRootedTreeOfCard · splitOf
├── Aho.lean            compatibility ⇒ existence of a tree
├── Consensus.lean      majority-rule consensus tree
├── Dendrogram.lean     ultrametric ⇒ tree (UPGMA structure theorem)
├── Binary.lean         witnesses of incompatible splits · binary trees
├── Quartet.lean        quartets / triplets · inference rules
├── QuartetUnique.lean  uniqueness of quartets on binary trees
├── SideSubtree.lean    side subtrees
├── InternalEdge.lean   leaf counts on both sides of an internal edge
├── Distance.lean       distances and the four-point condition
├── Algorithm/          Cherry · NJ · NNI · RF · UPGMA · BinaryCount
├── Stat/               ASTRAL · CASTER · MSC · NJst · Parsimony · Coalescent
│                       QuartetDecides · SVDQuartets · Stability · MassModel
└── Mathlib/            declarations Mathlib does not yet provide (kept separable
                        so they can be upstreamed later)
```

## Reproducible checks

Every check below is a self-contained script under `scripts/`; no external tooling.

| Want to check | Command |
|---|---|
| Size (modules / lines / declarations / build jobs) | `bash scripts/measure.sh` |
| Gap ledger and its seven buckets | `bash scripts/list_gaps.sh` |
| Machine evidence for each registered gap | `bash scripts/check_vacuous.sh` |
| Source-level markers on refuted statements | `bash scripts/check_refuted.sh` |
| Consistency of the dependency pins | `bash scripts/check_pins.sh` |
| Axiom dependencies of **all** closure theorems | `bash scripts/check_axioms_all.sh` |

## Dependency pinning

| Pinned where | Value | When to change |
|---|---|---|
| `lean-toolchain` | `leanprover/lean4:v4.35.0` (released, not a release candidate) | only when switching compiler |
| `lakefile.toml` (mathlib `rev`) | `v4.35.0` — a tag, **not** `master` | only when upgrading mathlib |
| `lake-manifest.json` (mathlib `rev`) | the commit that tag resolves to, must correspond to the toolchain tag | regenerated by `lake update`, committed together |

`bash scripts/check_pins.sh` verifies the three agree (CI runs it too).
**Do not** run `lake update` without editing `lakefile.toml` first: that silently moves the
manifest to a commit the build file never declared.

## What is formalized

No `sorry`, no `axiom`, no `opaque`: anything not yet proved is written as an explicit
`def … : Prop` gap, so the debt is visible and auditable (see the ledger below).

### Foundations: trees, splits, quartets

| Content | Main result | File |
|---|---|---|
| Cladograms and basic lemmas | `Cladogram` / `IsBinary` / degree–leaf relations | `Phylo/Core.lean` |
| Split systems and compatibility | **Splits-equivalence, both directions**: a tree yields a pairwise compatible family; a compatible family is realized by a tree | `Phylo/Split.lean`, `Phylo/Laminar.lean` |
| Aho–Buneman reconstruction | a compatible split system is displayed by a tree | `Phylo/Aho.lean` |
| Laminar families and clade dictionaries | `toCladogram` / `toRootedTreeOfCard` / `splitOf` | `Phylo/Laminar.lean` |
| Quartets, triplets, inference rules | `Topology` · `display` · Colonius–Schultze rules | `Phylo/Quartet.lean` |
| Uniqueness of quartets | a quartet on a 4-set is unique up to swap ⇒ `q_T` is well defined | `Phylo/QuartetUnique.lean` |
| Incompatible splits | incompatibility ⇒ two distinct quartets on one 4-leaf set | `Phylo/Binary.lean` |
| Internal edges | side subtrees are trees; at least two leaves on each side | `Phylo/SideSubtree.lean`, `Phylo/InternalEdge.lean` |

## Honest boundaries

The library is explicit about what is proved and what is assumed.

* **Quartet-wise consistency ⇒ tree isomorphism** is *proved*, not assumed:
  the shared lemma `QuartetDecidesTree` is a theorem, so `astral_iso` and `multiLocus_iso`
  carry no `hQD` hypothesis.
* **`MSCSampling.converges`** remains a structure field: this is where a law of large
  numbers enters, and it is not derived here.
* **`MSCFreq.majorizes`** is a structure field, but not an extra assumption: its whole
  mathematical content follows from the 4-taxon ILS weights
  (`Coalescent.MSCFreq.majorizes_of_quartetWeights`).
* **`MSCSite.majorizes`** is a structure field, but the anchor model *discharges* it:
  `AnchorModel.majorizes` proves the strict inequality (from the mass-majorization
  theorem) and `AnchorModel.toMSCSite` uses it to build a concrete `MSCSite`. For that
  model the field is a theorem, not an assumption.
* **NJ at the algorithm level is not formalized.** The greedy step is a theorem (see the
  table above), and "a tree metric determines its tree" is a theorem through
  `QuartetDecidesTree`; what is missing is an object for the NJ recursion itself, so
  "NJ applied to a tree metric returns that tree" is **not** claimed here.

## The gap ledger: how to read the seven buckets

Anything not yet proved is registered as `def … : Prop` and sorted into one of seven
buckets by `scripts/gap_ledger.py`. The script also prints the full signature of every
closure theorem, so a reader can check by hand whether extra hypotheses were consumed.

| Bucket | Meaning |
|---|---|
| **open** | no closure theorem and no machine counterexample — the only bucket that still needs mathematics |
| **closed** | a closure theorem with no extra hypotheses and no specialization |
| **conditional** | the closure theorem consumes a hypothesis absent from the `def`, or only proves a special case |
| **refuted** | a machine counterexample exists: the statement itself is false (a result, not a debt) |
| **legacy** | name ends in `_legacy`: an old form kept for the record, superseded by the current name |
| **archived** | whitelisted as carrying no provable content (degenerate by construction, or retired by decision) |
| **long-term open** | has provable content but is deliberately not pursued (conjecture-level) |

### Why "refuted" is not "unfinished"

A refuted entry was first written as `def … : Prop`, then proved **false**. It already has
a conclusion; it is not waiting for a proof.

The reader risk is real, though: `grep gap` mixes false statements with genuine targets.
Read the bucket output of `bash scripts/list_gaps.sh` first, then the source. The source is
marked as well — every refuted `def` carries a first docstring line naming its machine
counterexample, and `bash scripts/check_refuted.sh` enforces that the marker exists and
points at the right theorem.

### Degenerate registrations

Some registered statements are true for trivial reasons: their content is bound by an
`∃` and can be satisfied by a degenerate witness. Those are still listed, and
`bash scripts/check_vacuous.sh` classifies every registered gap as having a concrete
instance, a free slot, or no instance at all — no entry may go unclassified.

Where a statement is degenerate by construction, it has been **demoted out of the
"closed" bucket** rather than deleted: demotion changes a label, never the evidence.
Nothing is removed, and no theorem is renamed.

### Two ways to read the ledger

* **Bucket-relative**: every registered statement has a decided status.
* **Instance-relative**: some closed statements are true but not yet used on any concrete
  object and have no downstream consumer. That is a statement about *usage*, not about
  truth, and it is reported rather than folded into any headline claim.

This README deliberately quotes **no counts**. Numbers go stale silently and a stale
number is a false statement; the only authoritative figures are the live outputs of the
scripts above, which anyone can rerun.

## Scope of the repository

**Tracked**: `Phylo/**` and `Phylo.lean` (the library) · `scripts/**` (guards and
measurement) · `README.md` · `lakefile.toml` · `lake-manifest.json` · `lean-toolchain` ·
`.github/workflows/`.

**Not tracked** (`.gitignore`): handover notes and work logs (`HANDOVER.md`,
`MEMORY.md`, …), scratch scripts, `.lake/`. Process documents — reviews, audits, work
orders — do not enter the repository: only maintainable results and rerunnable guards do.
